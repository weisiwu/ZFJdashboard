# Marker Tracker — 产品需求文档 (PRD)

> **项目名称**：心脏造影序列双 Marker 跟踪与距离变化曲线系统
> **项目代号**：marker-tracker
> **版本**：v2.0
> **日期**：2026-04-19
> **状态**：Beta（Phase 2 核心功能已实现）

---

## 一、项目背景

### 1.1 业务场景

医生在心脏造影诊断中，需要观察两个固定 marker（标记物）在造影序列全程中的距离变化情况。当前流程依赖人工逐帧观察，效率低、可重复性差。

### 1.2 核心诉求

将"医生肉眼观察两个黑点的距离变化"升级为**系统自动跟踪并输出完整的距离-时间曲线**，提升测量效率和可重复性。

### 1.3 目标用户

| 角色 | 使用方式 |
|------|----------|
| 临床医生 | 导入造影序列 → 首帧点选 marker → 获取距离曲线和统计报告 |
| 影像科研人员 | 批量处理 DICOM 序列 → 导出结构化数据用于研究 |

## 二、功能需求

### 2.1 输入规格

| 输入类型 | 优先级 | 说明 |
|----------|--------|------|
| DICOM 多帧造影文件 | **P0** | 优先支持，保留原始像素、帧序、时间、空间元信息 |
| DICOM 单帧序列 | P1 | 多个单帧 DICOM 组成的时序 |
| MP4 / AVI 视频 | P1 | 兜底格式，fps 从文件头获取或由用户指定 |

### 2.2 初始化方式

| 方式 | 优先级 | 说明 |
|------|--------|------|
| 首帧人工点选两个 marker 中心 | **P0** | PoC 阶段默认方式，风险最低 |
| 首帧半自动定位 + 人工确认 | P1 | 系统建议候选位置，人工确认或修正 |
| 全自动首帧检测 | P2 | 后续版本，需积累标注数据 |

### 2.3 逐帧跟踪

| 需求项 | 优先级 | 验收标准 |
|--------|--------|----------|
| 逐帧定位两个 marker 的中心坐标 | **P0** | 输出 `p1(frame), p2(frame)` |
| 维持 A/B 标记身份一致性 | **P0** | 串 ID 率 < 1%（标准样本） |
| 输出每帧跟踪置信度分数 | **P0** | 分数范围 [0, 1]，低于阈值标记为低置信度 |
| 逐帧位移跳变检测 | P1 | 帧间位移超过阈值时触发告警 |
| 失追恢复（扩大搜索窗） | P1 | 一级恢复成功率 > 80%（标准样本） |
| 人工重置入口 | P1 | 跟丢后允许用户重新点选继续跟踪 |

### 2.4 距离曲线输出

| 输出项 | 优先级 | 说明 |
|--------|--------|------|
| 原始距离曲线 `d(frame)` | **P0** | 逐帧欧氏距离，单位 px |
| 平滑距离曲线 | P1 | Savitzky-Golay 或移动平均，**不覆盖原始值** |
| 距离曲线 `d(t)` | P1 | 横轴换算为真实时间（ms），依赖 DICOM Frame Time Vector 或 fps |
| 距离曲线 `d_mm(t)` | P2 | 纵轴换算为毫米，依赖 Pixel Spacing 或人工校准 |

### 2.5 统计报告

| 统计量 | 优先级 |
|--------|--------|
| 最大距离 d_max | **P0** |
| 最小距离 d_min | **P0** |
| 峰峰值 d_pp = d_max - d_min | **P0** |
| 平均距离 d_mean | **P0** |
| 标准差 d_std | P1 |
| 低置信度帧数量和占比 | P1 |
| 串 ID 事件次数 | P1 |
| 缺失帧列表 | P1 |

### 2.6 可视化输出

| 输出 | 优先级 | 说明 |
|------|--------|------|
| 距离变化曲线图（含原始+平滑） | **P0** | PNG/PDF |
| 关键帧截图（marker 位置叠加显示） | P1 | 首帧、d_max帧、d_min帧、末帧、低置信度帧 |
| 轨迹叠加图 | P2 | A/B 轨迹叠加在首帧上 |

### 2.7 数据导出

| 格式 | 优先级 | 内容 |
|------|--------|------|
| CSV | **P0** | frame, p1_x, p1_y, p2_x, p2_y, distance_px, score1, score2, confidence |
| JSON | P1 | 完整结构化结果（含元信息、统计量、曲线数据） |
| PNG/PDF | P0 | 曲线图 |

## 三、非功能需求

### 3.1 性能

| 指标 | 要求 |
|------|------|
| 单序列处理时间（200帧） | < 30 秒 |
| 内存峰值 | < 2 GB |
| 单帧跟踪耗时 | < 50 ms |

### 3.2 质量

| 指标 | 目标值（标准样本） | 说明 |
|------|---------------------|------|
| 轨迹完整率 | ≥ 95% | 连续可用帧占比 |
| 低置信度帧比例 | ≤ 10% | 标准样本 |
| 串 ID 率 | < 1% | A/B 身份交换次数 |
| 曲线重复性（CV） | < 2% | 同序列重复运行的距离 CV |

### 3.3 可靠性

- 低置信度帧必须明确标记，**不得伪造成高置信度**
- 跟丢后宁可中断曲线，也不输出虚假连续结果
- 所有中间结果可追溯（位置、分数、模板每帧保留）

### 3.4 可扩展性

- 六段式模块架构，各模块可独立替换
- 支持后续接入深度学习检测器（YOLO Track 等）
- 支持批量处理多序列

## 五、约束与假设

### 5.1 前提假设

1. 输入序列中始终存在且仅存在**两个** marker
2. Marker 在首帧中肉眼可见且可点选
3. PoC 阶段接受像素级结果，不要求毫米精度
4. 造影序列中存在心脏搏动和呼吸运动
5. Marker 外观相对稳定（非剧烈形变）

### 5.2 已知约束

1. Marker 可能因心脏运动出现短时遮挡
2. MP4 输入缺少时间轴和空间元信息
3. 不同设备的 DICOM 元信息完整度不一致
4. 视频压缩可能降低匹配稳定性

### 5.3 不做的事（当前阶段）

- 不做全自动首帧检测（P2）
- 不做多 marker（>2）跟踪
- 不做三维重建或多视角
- 不做实时处理（离线分析为主）
- 不做 DICOM Structured Report 标准输出

## 六、验收标准

### PoC 验收（Phase 1）

| 序号 | 验收项 | 通过条件 |
|------|--------|----------|
| A1 | 标准 DICOM 样本能跑完全程 | 轨迹完整率 ≥ 95% |
| A2 | 距离曲线走势符合肉眼观察 | 医生确认曲线形态合理 |
| A3 | 低置信度帧能被识别 | 无坏帧被伪装为高置信度 |
| A4 | CSV 导出完整 | 每帧 8 列数据无缺失 |
| A5 | 曲线重复性 | 同序列跑 3 次，距离 CV < 5% |
| A6 | 异常样本不输出假结果 | 跟丢段明确标记，不强行连续 |
