## RAPTOR 是什么

RAPTOR（Recursive Abstractive Processing for Tree-Organized Retrieval）是一种用于长文档检索增强的预处理技术，2024 年由斯坦福大学研究人员提出 [[1]](https://arxiv.org/abs/2401.18059)。

核心思想：**通过递归聚类和摘要构建层次化树形索引，同时捕捉文档的整体主题和细节信息**。

### 解决的问题

传统 RAG 方法存在一个关键缺陷：**只检索短连续文本块**。

示例：灰姑娘童话，问题"灰姑娘是如何获得幸福结局的？"

- 传统 top-k 检索：返回几个短片段，无法覆盖完整故事线
- RAPTOR：从树形结构中检索不同层级的摘要，既有整体情节理解，又有具体细节

### 核心价值

| 传统 RAG | RAPTOR |
|----------|--------|
| 检索短连续块 | 检索不同粒度的摘要 |
| 无法处理多跳问答 | 支持跨段落推理 |
| 丢失全局视角 | 同时保留全局和局部信息 |
| 按文本顺序切分 | 按语义相似性聚类 |

## RAPTOR 的工作原理

### 树形结构构建

RAPTOR 从下往上构建树形结构 [[1]](https://arxiv.org/html/2401.18059v1)：

```
                    [根节点：全书摘要]
                   /                    \
          [中间节点：章节摘要]    [中间节点：主题摘要]
            /        \                  /        \
      [叶节点]  [叶节点]          [叶节点]  [叶节点]
       块1-5     块6-10            块11-15   块16-20
```

**构建步骤**：

1. **分块**：将文档切分为 100 token 的短块（保持句子完整性）
2. **向量化**：使用 SBERT 等模型生成 embedding
3. **聚类**：基于语义相似性聚类（而非文本顺序）
4. **摘要**：对每个聚类生成摘要
5. **递归**：对摘要重复 3-4 步，直到无法继续聚类

### 聚类算法

RAPTOR 使用**软聚类**（Gaussian Mixture Models, GMM）[[1]](https://arxiv.org/html/2401.18059v1)：

- **软聚类**：一个文本块可以属于多个聚类
- **原因**：文本往往涉及多个主题，应出现在多个摘要中
- **降维**：使用 UMAP 降低 embedding 维度，改善高维空间聚类效果

聚类流程：

```
原始块 → UMAP降维 → GMM聚类 → 确定最优聚类数（BIC准则）
```

### 检索策略

RAPTOR 提供两种检索策略 [[1]](https://arxiv.org/html/2401.18059v1)：

#### 1. 树遍历（Tree Traversal）

```
步骤：
1. 从根节点层开始，计算查询与所有根节点的相似度
2. 选择 top-k 最相关的根节点
3. 进入这些节点的子节点层，再次选择 top-k
4. 递归直到叶节点
5. 拼接所有选中节点的内容
```

特点：逐层深入，从宏观到微观。

#### 2. 扁平树（Collapsed Tree）

```
步骤：
1. 将所有层级的节点"压平"到同一层
2. 计算查询与所有节点的相似度
3. 选择 top-k 最相关的节点（直到达到 token 限制）
```

特点：更灵活，可以同时检索高层摘要和底层细节。

**论文实验结论**：扁平树方法效果更好，因为它允许根据问题自动选择合适的粒度层级 [[1]](https://arxiv.org/html/2401.18059v1)。

## RAGFlow 中的 RAPTOR 实现

RAGFlow v0.6.0 集成了 RAPTOR 功能 [[2]](https://ragflow.com.cn/docs/dev/enable_raptor)。

### 基本原理

RAGFlow 的实现流程：

```
原始文档 → 分块 → 语义聚类 → LLM摘要 → 递归聚类摘要 → 树形索引
```

叶节点（蓝色）：原始块
根节点（橙色）：递归摘要生成的更高层级块

### 使用场景

RAPTOR 专为**多跳问答**设计 [[2]](https://ragflow.com.cn/docs/dev/enable_raptor)：

- 问题与答案之间存在语义鸿沟
- 需要跨段落整合信息
- 涉及复杂、多步推理

示例问题：

- "全书的主要论点是如何展开的？"
- "主角的性格变化经历了哪些阶段？"
- "不同章节讨论的技术方案有什么关联？"

### 前提条件

- 已配置系统默认聊天模型（用于摘要生成）
- 了解内存、计算和 token 成本

## RAGFlow 中启用 RAPTOR

### 步骤 1：配置知识库

进入知识库的**配置**页面，打开**使用 RAPTOR 增强检索**开关 [[2]](https://ragflow.com.cn/docs/dev/enable_raptor)。

### 步骤 2：调整参数

| 参数 | 默认值 | 最大值 | 说明 |
|------|--------|--------|------|
| **提示词** | 内置模板 | - | 摘要聚类内容时使用的提示词 |
| **最大 Token 数** | 256 | 2048 | 每个摘要块的最大 token 数 |
| **阈值** | 0.1 | 1.0 | 聚类相似度阈值，越高聚类越少 |
| **最大聚类数** | 64 | 1024 | 最多创建的聚类数 |
| **随机种子** | - | - | 可选，用于复现结果 |

**参数调优建议**：

| 场景 | 阈值 | 最大聚类数 | 最大 Token |
|------|------|------------|------------|
| 长文档（书籍） | 0.1 | 128 | 512 |
| 中等文档（论文） | 0.2 | 64 | 256 |
| 短文档（文章） | 不推荐使用 RAPTOR | - | - |

### 步骤 3：生成 RAPTOR 索引

1. 进入知识库的**文件**页面
2. 点击右上角**生成**按钮
3. 从下拉菜单选择**RAPTOR**
4. 等待构建完成

### 步骤 4：验证生成结果

返回**配置**页面，RAPTOR 字段显示：

- `未生成` → 尚未构建
- `生成于（时间戳）` → 已构建完成

可以点击回收站按钮删除重建。

### 步骤 5：使用 RAPTOR 检索

一旦生成 RAPTOR 树形结构：

- Chat Assistant 自动使用 RAPTOR 检索
- 检索代理组件默认使用 RAPTOR

## 实操案例：长篇小说多跳问答

### 场景

假设你有一本 10 万字的小说，希望构建知识库回答涉及全书情节的问题。

### 步骤 1：创建知识库

名称：小说知识库

### 步骤 2：上传文档

上传小说全文（TXT 或 PDF 格式）。

### 步骤 3：配置 RAPTOR

| 参数 | 设置 | 原因 |
|------|------|------|
| 阈值 | 0.1 | 长文档需要更多聚类 |
| 最大聚类数 | 128 | 覆盖全书主题 |
| 最大 Token | 512 | 摘要需要足够空间 |

### 步骤 4：生成 RAPTOR 索引

点击生成 → RAPTOR，等待处理完成。

### 步骤 5：测试多跳问答

**问题**：主角的性格变化经历了哪些阶段？每个阶段的转折点是什么？

**传统 RAG 的困境**：

- 检索到的是分散的段落片段
- 无法覆盖全书时间线
- 缺少整体视角

**RAPTOR 的优势**：

- 根节点摘要：全书情节主线
- 中间节点摘要：各章节主题
- 叶节点：具体情节细节

**回答示例**：

```
主角性格变化分为三个阶段：

1. 初期（第1-10章）：天真善良
   - 转折点：遭遇背叛事件
   - 来源：第5章摘要节点 + 第5章第3段

2. 中期（第11-30章）：愤世嫉俗
   - 转折点：导师的引导
   - 来源：第20章摘要节点 + 第18章第7段

3. 后期（第31-50章）：成熟稳重
   - 转折点：最终决战
   - 来源：全书摘要节点 + 第45章第2段
```

## 实操案例二：学术论文跨章节问答

### 场景

你有一份 50 页的技术白皮书，包含方法论、实验设计、结果分析等多个章节，希望构建知识库回答涉及跨章节的问题。

### 步骤 1：创建知识库

名称：技术白皮书知识库

### 步骤 2：上传文档

上传 PDF 格式的技术白皮书。

### 步骤 3：配置 RAPTOR

| 参数 | 设置 | 原因 |
|------|------|------|
| 阈值 | 0.2 | 论文结构相对清晰 |
| 最大聚类数 | 64 | 中等长度文档 |
| 最大 Token | 256 | 摘要保持精炼 |

### 步骤 4：生成 RAPTOR 索引

点击生成 → RAPTOR，等待处理完成。

### 步骤 5：测试跨章节问答

**问题**：论文提出的核心方法与传统方案相比有哪些优势？这些优势在实验中是如何验证的？

**传统 RAG 的困境**：

- 方法论章节和实验章节被分开检索
- 无法建立"方法-实验"的对应关系
- 检索结果碎片化，需要人工整合

**RAPTOR 的优势**：

- 聚类按语义相似性组织，"方法优势"相关段落会被聚类在一起
- 摘要节点自动整合跨章节信息
- 检索时可以同时获取整体对比和具体数据

**回答示例**：

```
核心方法相比传统方案的优势：

1. 准确率提升 15%
   - 方法论：引入多模态融合机制（第3章摘要节点）
   - 实验验证：在数据集 A 上准确率从 78% 提升到 93%（第5章叶节点）

2. 推理速度提升 2 倍
   - 方法论：采用分层索引结构（第3.2节摘要节点）
   - 实验验证：平均响应时间从 200ms 降至 100ms（第5.3节叶节点）

3. 资源消耗降低 40%
   - 方法论：动态缓存策略（第4章摘要节点）
   - 实验验证：内存占用从 8GB 降至 4.8GB（第5.4节叶节点）

来源：全书摘要节点 + 第3章摘要节点 + 第5章叶节点
```

### 为什么 RAPTOR 适合学术论文

学术论文的特点：

- 章节间存在逻辑关联（方法 → 实验 → 结论）
- 同一主题可能分散在不同章节（如"对比分析"贯穿全文）
- 问题往往需要整合多处信息

RAPTOR 的聚类机制天然适配这种结构：

- 将"方法描述"和"实验验证"聚类到同一组
- 摘要节点自动建立关联
- 检索时一次性获取完整信息链

## RAPTOR 与知识图谱的对比

两者都用于多跳问答，但机制不同 [[2]](https://ragflow.com.cn/docs/dev/enable_raptor)：

| 特性 | RAPTOR | 知识图谱 |
|------|--------|----------|
| **构建方式** | 聚类 + 摘要 | 实体 + 关系提取 |
| **结构** | 树形层次 | 图结构 |
| **适用场景** | 长文档主题理解 | 实体关系推理 |
| **成本** | 中等（token 消耗） | 高（多次 LLM 调用） |
| **检索方式** | 语义相似度 | 图遍历 |

**选择建议**：

- 文档主题分散、需要整体理解 → RAPTOR
- 文档包含明确实体关系（人物、组织） → 知识图谱
- 复杂场景 → 两者结合使用

## RAPTOR 的设计思路

### 为什么需要树形结构

长文档天然具有层次结构 [[1]](https://arxiv.org/html/2401.18059v1)：

- 书籍：章节 → 段落 → 句子
- 论文：章节 → 小节 → 段落
- 报告：部分 → 条目 → 细节

传统 RAG 只检索叶子节点，丢失了上层结构信息。RAPTOR 通过摘要重建了这种层次。

### 为什么选择聚类而非顺序摘要

按文本顺序摘要的问题：

- 相邻段落可能主题不同
- 相同主题的段落可能分散在不同位置

聚类摘要的优势：

- 按语义相似性组织
- 同一聚类的段落共享主题
- 摘要更聚焦、更相关

### 为什么使用软聚类

文本的多主题特性 [[1]](https://arxiv.org/html/2401.18059v1)：

- 一段文字可能同时涉及"技术方案"和"成本分析"
- 硬聚类会强制选择一个主题
- 软聚类允许同时出现在多个摘要中

## 成本与性能考量

### Token 消耗

RAPTOR 的 token 消耗取决于：

- 原始文档长度
- 聚类数量
- 递归层数

**估算公式**：

```
总 token ≈ 原始 token × (1 + 聚类层数 × 压缩比)
```

示例：10 万字小说（约 15 万 token）

- 原始块：15 万 token
- 第一层摘要：假设 64 个聚类，每个 256 token = 1.6 万 token
- 第二层摘要：假设 8 个聚类，每个 512 token = 4 千 token
- 总计：约 17 万 token

### 计算时间

主要耗时环节：

1. 聚类计算：与块数量成正比
2. 摘要生成：与聚类数量成正比，每个聚类调用一次 LLM

**优化建议**：

- 使用更快的聊天模型（如 GPT-3.5-turbo）
- 适当增加阈值减少聚类数
- 对超长文档分批处理

### 何时不应使用 RAPTOR

| 场景 | 是否推荐 | 原因 |
|------|----------|------|
| 短文档（<5000 字） | ❌ | 成本高于收益 |
| FAQ 问答 | ❌ | 不需要多跳推理 |
| 精确匹配检索 | ❌ | 语义摘要可能丢失细节 |
| 长文档主题问答 | ✅ | 核心场景 |
| 跨段落推理 | ✅ | 核心场景 |
